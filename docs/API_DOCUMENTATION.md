# API Documentation

- **Base URL:** `/api/v1`
- **Format:** JSON only (`Accept: application/json`)
- **Interactive OpenAPI docs:** `http://localhost:8000/docs/api` (generated by Scramble from code; JSON at `/docs/api.json`). Available in the `local` environment; exposing it elsewhere requires the `viewApiDocs` gate.

## Response envelope

Every response (except `204 No Content`) uses the same envelope.

**Success**
```json
{
  "success": true,
  "data": { "...": "..." },
  "meta": { "request_id": "01938c1e-…" }
}
```

**Paginated success**
```json
{
  "success": true,
  "data": [ { "...": "..." } ],
  "meta": {
    "request_id": "…",
    "pagination": { "current_page": 1, "per_page": 25, "total": 240, "last_page": 10 }
  }
}
```

**Error**
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The given data was invalid.",
    "details": { "email": ["The email field is required."] }
  },
  "meta": { "request_id": "…" }
}
```

Clients should branch on `error.code`, not on `message`. Money values are serialized as **strings** with two decimals (`"125.50"`) — never parse them into binary floats for arithmetic.

## Error codes

| HTTP | `error.code` | Meaning |
|------|--------------|---------|
| 401 | `UNAUTHENTICATED` | No valid session/token. |
| 403 | `FORBIDDEN` | Authenticated but lacking permission or branch access. |
| 404 | `NOT_FOUND` | Unknown route or resource (also returned for resources of other tenants). |
| 405 | `METHOD_NOT_ALLOWED` | |
| 409 | `CONFLICT` / `IDEMPOTENCY_KEY_REUSED` / `IDEMPOTENCY_REQUEST_IN_PROGRESS` | State conflict / same key with a different payload / the first request with this key is still running (`Retry-After`). |
| 428 | `IDEMPOTENCY_KEY_REQUIRED` | Checkout sent without an `Idempotency-Key` header. |
| 419 | `CSRF_TOKEN_MISMATCH` | SPA must refresh `/sanctum/csrf-cookie`. |
| 422 | `VALIDATION_FAILED` | Field-level errors in `details`. |
| 422 | *domain code* | Business rule violation, e.g. `INSUFFICIENT_STOCK`, `CREDIT_LIMIT_EXCEEDED`, `DISCOUNT_NOT_ALLOWED`. Context in `details`. |
| 400 | `ORGANIZATION_CONTEXT_REQUIRED` | Platform admin called a tenant endpoint without `X-Organization-Id`. |
| 403 | `ACCOUNT_INACTIVE` / `ORGANIZATION_SUSPENDED` | Credential still valid but the account or tenant is blocked. |
| 403 | `BRANCH_ACCESS_DENIED` | `X-Branch-Id` is not an active branch the user may access. |
| 422 | `INVALID_CREDENTIALS`, `SESSION_UNAVAILABLE`, `INVALID_RESET_TOKEN` | Authentication failures (identical message for unknown e-mail and wrong password). |
| 422 | `CANNOT_MODIFY_OWN_ACCESS`, `LAST_ORGANIZATION_ADMIN`, `LAST_ACTIVE_BRANCH`, `SYSTEM_ROLE_READ_ONLY`, `ROLE_IN_USE` | Lock-out and integrity guards. |
| 422 | `IN_USE` | Record still referenced (deactivate it instead). |
| 422 | `INSUFFICIENT_STOCK` | Outgoing quantity exceeds stock and the branch does not allow negative stock. `details`: `variant_id`, `sku`, `store_id`, `batch_id`, `available`, `requested`. |
| 422 | `STORE_INACTIVE`, `UNKNOWN_PRODUCT`, `BATCH_EXPIRY_MISMATCH` | Stock posting guards: inactive store/branch, variant not in this organization, existing batch number with a different expiry date. |
| 422 | `TRANSFER_NOT_IN_TRANSIT` | Transfer was already received or cancelled. |
| 422 | `PURCHASE_ORDER_LOCKED`, `INVALID_STATUS_CHANGE`, `PURCHASE_ORDER_NOT_OPEN` | Only drafts can be edited; illegal status transition; receiving against a draft/cancelled/fully received order. |
| 409 | `CONFLICT` | A concurrent request saved a conflicting record (unique index); reload and retry. |
| 422 | `DISCOUNT_NOT_ALLOWED` | Manual discount without `sales.discount`, above the product's max. %, or larger than the amount (`details.line`, `details.max_percent`). |
| 422 | `CUSTOMER_REQUIRED`, `CREDIT_SALE_NOT_ALLOWED`, `CREDIT_LIMIT_EXCEEDED` | An amount left due needs a customer, `sales.credit` and room in the credit limit (`details.outstanding`, `credit_limit`, `available`, `due`). |
| 422 | `NON_CASH_OVERPAYMENT` | Card/mobile payments exceed the total (only cash gives change). |
| 422 | `PRODUCT_NOT_SELLABLE`, `HELD_SALE_GONE`, `SALE_ALREADY_CANCELLED` | Scanned product archived/inactive; held cart already checked out or discarded; repeated cancellation. |
| 422 | `CASH_SESSION_REQUIRED` | Checkout, or any cash in/out (refund, collection, expense, cancellation), without an open register session of the caller in that branch (`details.branch_id`, `open_session_id` when it is open elsewhere). |
| 422 | `INSUFFICIENT_CASH` | A cash payout would take the drawer below zero (`details.available`, `required`). |
| 422 | `SESSION_ALREADY_OPEN`, `REGISTER_IN_USE`, `REGISTER_INACTIVE`, `SESSION_CLOSED` | One session per cashier and per register; inactive register; session already closed. |
| 422 | `SALE_HAS_RETURNS`, `SALE_CANCELLED` | A sale with returns cannot be cancelled; a cancelled sale cannot be returned. |
| 422 | `REFUND_MISMATCH`, `RETURN_ALREADY_DECIDED` | Refunds must add up to `details.refund_due` (`credit` is applied to the customer's balance); return already completed/rejected. |
| 422 | `PAYMENT_EXCEEDS_BALANCE` | A customer payment larger than what they owe (`details.outstanding`). |
| 422 | `ALREADY_VOIDED` | Expense/income entry already void. |
| 422 | `LOYALTY_NOT_AVAILABLE`, `LOYALTY_AMOUNT_INVALID`, `INSUFFICIENT_POINTS` | Program off; amount not a whole number of points or below the minimum; not enough points (`details.available`, `required`). |
| 422 | `PRIVILEGE_ESCALATION` | Granting/assigning permissions the actor lacks, or editing a more powerful user. `details.permissions` lists what is missing. |
| 404 | `STOREFRONT_NOT_FOUND` | Public storefront API: the host name serves no open store (unknown host, closed store, suspended organization). |
| 422 | `STOREFRONT_DOMAIN_REQUIRED` | Opening the storefront without a domain, or removing the last domain of an open store. |
| 422 | `MEDIA_NOT_FOUND` | A theme or menu points at media ids that are not in the organization's library (`details.media_ids`). |
| 422 | `MEGA_MENU_NOT_ALLOWED`, `MENU_TOO_LARGE` | Mega menu outside top-level items of the main menu; more than 200 menu items. |
| 422 | `CUSTOM_CSS_REJECTED` | Custom CSS breaks the policy (`<`, `@import`, `expression(`, escapes, `url()` outside `/storage/`, > 20 KB). |
| 422 | `INVALID_IMAGE`, `IN_USE` | Upload is not a readable image; media still used by the theme, a menu, a banner or a section. Also: a banner shown by a section (`details.sections`), a page a menu links to. |
| 422 | `BANNER_IN_USE`, `BANNER_NOT_FOUND`, `SECTION_ITEMS_INVALID` | Moving a banner used by a section to another placement; a section's banners missing or of the wrong placement (`details.banner_ids`); too few/many banners for the section or layout. |
| 422 | `BUTTON_LINK_REQUIRED`, `SCHEDULE_INVALID` | A banner button without label or link; a schedule whose end is not after its start. |
| 422 | `CONTENT_EMPTY`, `PAGE_NOT_FOUND`, `ORDER_MISMATCH`, `LIMIT_REACHED` | Rich text empty after sanitizing; a menu item linking to a missing page; a reorder that does not list every item exactly once; too many sections/banners/FAQ entries. |
| 422 | `TOKEN_INVALID` | Newsletter confirm/unsubscribe token unknown or expired. |
| 429 | `TOO_MANY_REQUESTS` | Rate limited; honour `Retry-After`. |
| 500 | `SERVER_ERROR` | Unexpected; quote `meta.request_id` when reporting. |
| 503 | `SERVICE_UNAVAILABLE` | Maintenance or dependency outage. |

## Cross-cutting headers

| Header | Direction | Purpose |
|--------|-----------|---------|
| `X-Request-Id` | both | Correlation id. Clients may send one (8–64 chars `[A-Za-z0-9-_.]`); the server always returns it. |
| `Idempotency-Key` | request | Required on `POST /pos/checkout`, `/returns`, `/returns/{id}/approve`, `/customer-payments`, `/expenses` and `/register-sessions/{id}/cash-movements`: 8–100 characters, one per logical operation (the SPA uses a UUID); reuse it when retrying. A replayed response carries `Idempotent-Replayed: true`. |
| `X-Branch-Id` | request | Active branch. Optional; when sent it must be an active branch of the organization that the user is assigned to (or `branches.access_all`). Branch-scoped endpoints (Phase 4+) require it. |
| `X-Organization-Id` | request | Platform admins only: organization to act in. Ignored for tenant users. |
| `X-XSRF-TOKEN` | request | SPA cookie auth CSRF token (sent automatically by the frontend client). |
| `Retry-After`, `X-RateLimit-*` | response | Rate-limit information. |

## Conventions

- **Pagination:** `?page=1&per_page=25` (max 100).
- **Sorting:** `?sort=name` / `?sort=-created_at` (prefix `-` for descending); only whitelisted columns.
- **Filtering:** plain, validated query parameters per endpoint, e.g. `?status=active&role_id=…`; date ranges `?from=2026-10-01&to=2026-10-31` (inclusive).
- **Search:** `?search=term` (case-insensitive, whitelisted columns).
- **Rate limits:** 120 requests/minute per user (or IP when unauthenticated) on the `api` group; credential endpoints (`auth` limiter) 5/min per e-mail+IP and 20/min per IP; public storefront (`storefront` limiter) 300/min per IP.
- **Identifiers:** UUIDv7 strings (device token ids are integers).
- **Versioning:** breaking changes go to `/api/v2`; additive changes stay in v1.

| POST | `/returns/{id}/approve` | tenant | `returns.approve` + `Idempotency-Key` | `{refunds: [...]}` → completed: stock back to the original batches (restock lines), serials released, credit applied, refunds booked (cash from the approver's session), loyalty reversed. `REFUND_MISMATCH`, `RETURN_ALREADY_DECIDED`. |
| POST | `/returns/{id}/reject` | tenant | `returns.approve` | `{reason}`. |
| GET / POST / PUT / DELETE | `/return-reasons[/{id}]` | tenant | read: any `returns.*`; write: `returns.manage` | `{name, restock_by_default, is_active}`; delete only unused (`IN_USE`). |
| GET | `/customer-payments` | tenant | `payments.view` | `customer_id`, `branch_id`, `search`. |
| POST | `/customer-payments` | tenant | `payments.collect` + `Idempotency-Key` | `{customer_id, branch_id, amount, method (cash, card, mobile_banking, bank_transfer, cheque), reference?, notes?}`; at most the outstanding balance (`PAYMENT_EXCEEDS_BALANCE`). Number `RCP-000001`. |
| GET | `/customers/{id}/statement` | tenant | `sales.view` or `payments.view` | Entries `sale` (+total), `sale_payment` (−paid at the till), `sale_cancellation` (−due), `sale_return` (−total), `refund` (+refunded), `payment` (−amount) with running `balance`; `from`/`to`. |
| GET | `/expense-categories` | tenant | `expenses.view` | `type` (`expense`, `income`). |
| POST / PUT / DELETE | `/expense-categories[/{id}]` | tenant | `expenses.manage` | `{type, name, is_active}` (name unique per type). |
| GET | `/expenses` | tenant | `expenses.view` | `type` (default `expense`), `branch_id`, `expense_category_id`, `method`, `from`/`to` (`occurred_on`), `voided`, `search`; `meta.totals.amount`, `meta.by_category[]`. |
| POST | `/expenses` | tenant | `expenses.manage` + `Idempotency-Key` | `{type, branch_id, expense_category_id, amount, method, occurred_on, reference?, party?, notes?}` → `EXP-000001` / `INC-000001`; cash through the caller's session. |
| GET | `/expenses/{id}` | tenant | `expenses.view` | One entry. |
| POST | `/expenses/{id}/void` | tenant | `expenses.manage` | `{reason}`; books the opposite payment; `ALREADY_VOIDED`. |
| GET / PUT | `/loyalty/settings` | tenant | read: `loyalty.*`, `customers.view` or `pos.sell`; write: `loyalty.manage` | `{is_enabled, spend_amount, points_per_spend, point_value, min_redeem_points}`. |
| GET | `/loyalty/balances?customer_ids[]=` | tenant | as settings read | `{customer_id: points}`. |
| GET | `/loyalty/customers/{id}` | tenant | as settings read | `balance`, `lifetime_earned`, `lifetime_redeemed`, latest 100 `transactions` (`earn`, `redeem`, `earn_reversal`, `redeem_reversal`, `refund`, `adjustment`). |
| POST | `/loyalty/customers/{id}/adjust` | tenant | `loyalty.manage` | `{points (signed), notes}`. |
| GET | `/notifications` | auth | — | Own in-app notifications (paginated), `unread=1`. Currently `inventory.low_stock`. |
| GET | `/notifications/unread-count` | auth | — | `{count}` for the bell. |
| POST | `/notifications/{id}/read`, `/notifications/read-all` | auth | — | Mark as read. |

All paths are relative to `/api/v1`.

### E-commerce track — storefront and media (E4)

Public storefront endpoints live under `/api/v1/store/*`: no authentication, the organization comes from the request's **host name** (`storefront_domains`; ADR-001). A closed storefront answers `404 STOREFRONT_NOT_FOUND`, except to signed-in staff of the organization holding `storefront.view` (`preview: true`). The planned surface is in `docs/ecommerce/API_PLAN.md`.

| Method & path | Permission | Notes |
|---------------|------------|-------|
| GET `/store/bootstrap` | public | Store name/description, theme tokens with media resolved to `{id, url, srcset, width, height, alt}`, live announcement (scheduled window applied), active menus as trees of visible items, `preview`. `ETag` / `If-None-Match` → 304. |
| GET `/storefront/settings` · PATCH | `storefront.view` · `storefront.manage` | `is_enabled`, `site_name`, `meta_description`. Defaults (closed, organization name) until first saved. |
| GET `/storefront/domains` · POST · PATCH `/{id}` · DELETE `/{id}` | view · manage | Host names only (lower-cased, globally unique); the first is primary; PATCH `{is_primary: true}`. |
| GET `/storefront/theme` · PUT | view · manage | Whole theme document (`colors`, `typography`, `shape`, `layout`, `logo_media_id`, `favicon_media_id`, `announcement`, `footer`); missing keys take defaults, unknown keys are dropped. `custom_css` only returned with `storefront.custom_css`. |
| PUT `/storefront/theme/custom-css` | `storefront.custom_css` | `{custom_css}`; policy-checked. |
| GET `/storefront/menus` · GET `/{id}` · POST · PATCH `/{id}` · DELETE `/{id}` | view · manage | One menu per location `main`, `mobile`, `footer_1`..`footer_3`. |
| PUT `/storefront/menus/{id}/items` | `storefront.manage` | Whole ordered tree `{items: [{label, url, open_in_new_tab, is_visible, is_mega, mega_columns, image_media_id, children}]}`; ≤ 3 levels, ≤ 200 items; links `/path` or http(s). |
| GET `/media` · POST · PATCH `/{id}` · DELETE `/{id}` | `media.manage` | Upload multipart `file` (JPEG/PNG/WebP/GIF ≤ 5 MB, ≤ 6000 px) + `alt`; identical bytes return the existing item (200). WebP renditions 320/640/1280 px by a queued job. |

Pages: every path outside `/api`, `/sanctum`, `/storage`, `/admin`, `/docs`, `/up` is the storefront HTML shell (built `storefront.html` with server-written title, description, canonical, Open Graph and favicon, and the inlined bootstrap payload); unknown storefront paths answer 404 with `X-Robots-Tag: noindex`.

### E-commerce track — content and homepage (E5)

| Method & path | Permission | Notes |
|---------------|------------|-------|
| GET `/store/homepage` | public | `{sections, preview}`: live sections in order. | GET `/store/pages/{slug}` | public | Published page whose publication time has come: `{slug, title, template, body_html, published_at, seo_title, seo_description, updated_at}`; `faq` template adds `faq: [{group, items: [{id, question, answer_html}]}]`. Otherwise `404 NOT_FOUND`. |
