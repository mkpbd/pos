# API Documentation

- **Base URL:** `/api/v1`
- **Format:** JSON only (`Accept: application/json`)
- **Interactive OpenAPI docs:** `http://localhost:8000/docs/api` (generated by Scramble from code; JSON at `/docs/api.json`). Available in the `local` environment; exposing it elsewhere requires the `viewApiDocs` gate.

## Response envelope

Every response (except `204 No Content`) uses the same envelope.

**Success**
```json
{
  "success": true,
  "data": { "...": "..." },
  "meta": { "request_id": "01938c1e-…" }
}
```

**Paginated success**
```json
{
  "success": true,
  "data": [ { "...": "..." } ],
  "meta": {
    "request_id": "…",
    "pagination": { "current_page": 1, "per_page": 25, "total": 240, "last_page": 10 }
  }
}
```

**Error**
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The given data was invalid.",
    "details": { "email": ["The email field is required."] }
  },
  "meta": { "request_id": "…" }
}
```

Clients should branch on `error.code`, not on `message`. Money values are serialized as **strings** with two decimals (`"125.50"`) — never parse them into binary floats for arithmetic.

## Error codes

| HTTP | `error.code` | Meaning |
|------|--------------|---------|
| 401 | `UNAUTHENTICATED` | No valid session/token. |
| 403 | `FORBIDDEN` | Authenticated but lacking permission or branch access. |
| 404 | `NOT_FOUND` | Unknown route or resource (also returned for resources of other tenants). |
| 405 | `METHOD_NOT_ALLOWED` | |
| 409 | `CONFLICT` / `IDEMPOTENCY_KEY_REUSED` | State conflict / same key with a different payload. |
| 419 | `CSRF_TOKEN_MISMATCH` | SPA must refresh `/sanctum/csrf-cookie`. |
| 422 | `VALIDATION_FAILED` | Field-level errors in `details`. |
| 422 | *domain code* | Business rule violation, e.g. `INSUFFICIENT_STOCK`, `CREDIT_LIMIT_EXCEEDED`, `DISCOUNT_NOT_ALLOWED`. Context in `details`. |
| 400 | `ORGANIZATION_CONTEXT_REQUIRED` | Platform admin called a tenant endpoint without `X-Organization-Id`. |
| 403 | `ACCOUNT_INACTIVE` / `ORGANIZATION_SUSPENDED` | Credential still valid but the account or tenant is blocked. |
| 403 | `BRANCH_ACCESS_DENIED` | `X-Branch-Id` is not an active branch the user may access. |
| 422 | `INVALID_CREDENTIALS`, `SESSION_UNAVAILABLE`, `INVALID_RESET_TOKEN` | Authentication failures (identical message for unknown e-mail and wrong password). |
| 422 | `CANNOT_MODIFY_OWN_ACCESS`, `LAST_ORGANIZATION_ADMIN`, `LAST_ACTIVE_BRANCH`, `SYSTEM_ROLE_READ_ONLY`, `ROLE_IN_USE` | Lock-out and integrity guards. |
| 422 | `IN_USE` | Record still referenced (deactivate it instead). |
| 422 | `INSUFFICIENT_STOCK` | Outgoing quantity exceeds stock and the branch does not allow negative stock. `details`: `variant_id`, `sku`, `store_id`, `batch_id`, `available`, `requested`. |
| 422 | `STORE_INACTIVE`, `UNKNOWN_PRODUCT`, `BATCH_EXPIRY_MISMATCH` | Stock posting guards: inactive store/branch, variant not in this organization, existing batch number with a different expiry date. |
| 422 | `TRANSFER_NOT_IN_TRANSIT` | Transfer was already received or cancelled. |
| 422 | `PURCHASE_ORDER_LOCKED`, `INVALID_STATUS_CHANGE`, `PURCHASE_ORDER_NOT_OPEN` | Only drafts can be edited; illegal status transition; receiving against a draft/cancelled/fully received order. |
| 409 | `CONFLICT` | A concurrent request saved a conflicting record (unique index); reload and retry. |
| 422 | `PRIVILEGE_ESCALATION` | Granting/assigning permissions the actor lacks, or editing a more powerful user. `details.permissions` lists what is missing. |
| 429 | `TOO_MANY_REQUESTS` | Rate limited; honour `Retry-After`. |
| 500 | `SERVER_ERROR` | Unexpected; quote `meta.request_id` when reporting. |
| 503 | `SERVICE_UNAVAILABLE` | Maintenance or dependency outage. |

## Cross-cutting headers

| Header | Direction | Purpose |
|--------|-----------|---------|
| `X-Request-Id` | both | Correlation id. Clients may send one (8–64 chars `[A-Za-z0-9-_.]`); the server always returns it. |
| `Idempotency-Key` | request | Required on checkout and payment endpoints (Phase 5+). A UUID per user action; retries reuse it. |
| `X-Branch-Id` | request | Active branch. Optional; when sent it must be an active branch of the organization that the user is assigned to (or `branches.access_all`). Branch-scoped endpoints (Phase 4+) require it. |
| `X-Organization-Id` | request | Platform admins only: organization to act in. Ignored for tenant users. |
| `X-XSRF-TOKEN` | request | SPA cookie auth CSRF token (sent automatically by the frontend client). |
| `Retry-After`, `X-RateLimit-*` | response | Rate-limit information. |

## Conventions

- **Pagination:** `?page=1&per_page=25` (max 100).
- **Sorting:** `?sort=name` / `?sort=-created_at` (prefix `-` for descending); only whitelisted columns.
- **Filtering:** plain, validated query parameters per endpoint, e.g. `?status=active&role_id=…`; date ranges `?from=2026-10-01&to=2026-10-31` (inclusive).
- **Search:** `?search=term` (case-insensitive, whitelisted columns).
- **Rate limits:** 120 requests/minute per user (or IP when unauthenticated) on the `api` group; credential endpoints (`auth` limiter) 5/min per e-mail+IP and 20/min per IP.
- **Identifiers:** UUIDv7 strings (device token ids are integers).
- **Versioning:** breaking changes go to `/api/v2`; additive changes stay in v1.

All paths are relative to `/api/v1`.

Example — create a product with variants:
```json
POST /api/v1/products
{
  "name": "Cotton Polo Shirt", "type": "standard", "unit_id": "0193…", "tax_rate_id": "0193…",
  "category_id": null, "brand_id": null, "track_stock": true, "max_discount_percent": "10", "is_active": true,
  "options": [{ "name": "Size", "values": ["M", "L"] }],
  "variants": [
    { "sku": null, "option_values": { "Size": "M" }, "purchase_price": "320.00", "selling_price": "450.00", "barcodes": ["4006381333931"] },
    { "sku": "POLO-L", "option_values": { "Size": "L" }, "purchase_price": "320.00", "selling_price": "450.00", "barcodes": [] }
  ]
}
```
Prices are decimal strings (2 places; reorder level 3). Blank SKUs become `SKU-000001`, … Numeric 8/12/13/14-digit barcodes must have a valid GS1 check digit. Field errors use dotted paths (`variants.1.barcodes.0`).

Example — receive goods against a purchase order (stock in + supplier invoice in one transaction):
```json
POST /api/v1/purchasing/receipts
{
  "supplier_id": "0193…", "store_id": "0193…", "purchase_order_id": "0193…",
  "supplier_invoice_number": "PRAN-5521", "invoice_date": "2026-10-31", "due_date": null,
  "lines": [
    { "variant_id": "0193…", "purchase_order_line_id": "0193…", "quantity": "96", "unit_cost": "18.00", "tax_rate": "15" },
    { "variant_id": "0193…", "quantity": "24", "unit_cost": "110.00", "batch_number": "MJ-2611", "expires_on": "2027-05-31" }
  ]
}
```
Response `data`: `number` `GRN-000002`, `subtotal`/`tax_total`/`total` computed server-side (decimal strings), `due_date` filled from payment terms, `lines[].line_total`. Receiving more than is still open on the order → `422 VALIDATION_FAILED` with `lines.0.quantity: "Only 40.000 still open on the order."`.
